# v0.17.0 — Redis + BullMQ Crawl Infrastructure

The crawler is now a real asynchronous queue-backed worker instead of an in-memory development queue.

## Added

- Redis-backed crawl job state.
- BullMQ `crawl.queue`.
- One BullMQ job per URL for horizontal worker scaling.
- Retry policy: 3 attempts with exponential backoff.
- Queue priority mapping.
- Concurrency controlled by `CRAWL_CONCURRENCY`.
- Global crawl rate limiter controlled by `CRAWL_RATE_LIMIT_MAX` / `CRAWL_RATE_LIMIT_DURATION_MS`.
- Atomic optimistic Redis updates to avoid lost progress when multiple browser workers update one crawl job concurrently.
- Per-URL status, error and result storage in Redis.
- Cancellation flag respected by workers before starting a URL.
- Graceful worker shutdown.
- Existing search worker remains intact.

## Environment

```env
REDIS_URL=redis://localhost:6379
CRAWL_CONCURRENCY=2
CRAWL_RATE_LIMIT_MAX=20
CRAWL_RATE_LIMIT_DURATION_MS=1000
REQUEST_TIMEOUT=30000
BROWSER_NO_SANDBOX=false
```

## Architecture

```text
Next.js
   |
   v
Nest API ----> Redis state
   |
   +---------> BullMQ crawl.queue
                    |
          +---------+---------+
          v                   v
      Worker #1            Worker #2
      Chromium             Chromium
          |                   |
          +---------+---------+
                    |
                    v
              Redis results
```

PostgreSQL persistence for crawl results and automatic lead creation is the next hardening step (v0.18).
