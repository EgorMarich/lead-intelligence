This release moves the architecture from prototype-only storage toward a persistent production model.

## Important design decisions

### Organization isolation

Every business-facing table is scoped to `organization_id` either directly or through a parent relation.

### Lead lifecycle

Lead status is stored independently from scoring. A lead can become `CONVERTED` while retaining its original and historical score snapshots.

### Score explainability

Scoring profiles are versioned. A score references the exact profile version used to calculate it.

### Import idempotency

Imported leads can be deduplicated with:
`organization_id + source + source_external_id`.

### Soft delete

Leads use `deleted_at`, allowing audit history and recovery.

### Activity history

Changes should be appended to `lead_activities`, rather than overwriting the sales history.
