# v0.16.0 — Real Browser Crawler

Lead Intelligence now has a real Chromium crawler behind the `CrawlerAdapter` abstraction.

## What changed

- Added Puppeteer-based `BrowserCrawlerAdapter`.
- JavaScript-rendered pages are loaded in a real headless browser.
- Navigation timeout and browser lifecycle are controlled centrally.
- Images, media and fonts are skipped to reduce bandwidth.
- Redirect destinations are validated again before being trusted.
- SSRF protections reject localhost, private/link-local IPv4/IPv6 ranges and non-standard ports.
- Extracts title, description, language, visible text, emails, phones and up to 200 links.
- Detects Telegram, VK, WhatsApp and Instagram links.
- Detects WordPress, Bitrix, Tilda, Shopify, Wix, YCLIENTS, DIKIDI and common analytics.
- Detects booking, contact, analytics and ecommerce signals.
- Crawl jobs now retain per-URL results in the development queue.
- Failed URLs increment `failedUrls` while the job can continue processing the remaining URLs.
- Browser is closed during application shutdown.

## API flow

`POST /api/v1/crawl/jobs` creates a job.

`POST /api/v1/crawl/jobs/:id/run` executes it with Chromium.

`GET /api/v1/crawl/jobs/:id` returns progress and collected page results.

## Production note

The current job queue remains an in-memory development adapter. v0.17 will move execution to Redis + BullMQ with concurrency, retries/backoff, per-host rate limits, progress events and stalled-job recovery.

Puppeteer downloads a compatible browser during dependency installation. In Docker/CI, keep the browser dependencies explicit and use `BROWSER_NO_SANDBOX=true` only in an appropriately isolated container when required by the runtime.
