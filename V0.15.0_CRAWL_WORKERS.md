# v0.15.0 — Crawl Workers

Adds tenant-scoped crawl job orchestration with queue/worker/adapter boundaries.

Endpoints:
- POST /api/crawl/jobs
- GET /api/crawl/jobs
- GET /api/crawl/jobs/:id
- POST /api/crawl/jobs/:id/run

The current queue is an in-memory development adapter. Production implementation should replace it with Redis/BullMQ, retries, backoff, concurrency, rate limits, cancellation and stalled-job recovery. BrowserCrawlerAdapter is the seam for Puppeteer/Playwright.

Pipeline: source/import → crawl job → worker → browser crawler → extracted signals → deduplication → lead creation → scoring → CRM.
